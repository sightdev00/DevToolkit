# 终端复用与 Agent 终端工具

本目录收录需要长期保留终端状态、远程重连、组织多个交互式进程，或统一管理多个 Coding Agent 的工具。

## 工具边界

| 工具 | 核心对象 | 最适合 | 不应被误认为 |
|---|---|---|---|
| [tmux](./tmux/) | session / window / pane / PTY 进程 | SSH 断线保护、通用 Shell、日志、编译、训练、服务调试 | 进程检查点系统、服务管理器、Agent 状态管理器 |
| [Herdr](./herdr/) | workspace / tab / pane / Agent 状态 | 多个 Coding Agent 并行工作、状态汇总、远程接入和 Agent 编排 | tmux 的无条件替代品、任务正确性评价器、生产服务守护器 |

## 选择方法

优先选择 tmux，当主要需求是：

- 在 Linux 服务器上保持 Shell、编译、训练或日志会话；
- 需要成熟、普及、脚本化能力强的终端复用器；
- 依赖精细快捷键、状态栏、插件或现有团队规范；
- 环境权限受限，只能安装发行版自带软件。

优先试用 Herdr，当主要需求是：

- 同时运行多个 Codex、Claude Code、OpenCode、Hermes 等 Coding Agent；
- 需要知道哪个 Agent 正在工作、等待输入、阻塞或已结束；
- 希望通过 CLI 或 Socket API 创建 pane、发送任务、等待状态和读取结果；
- 希望保留真实终端界面，而不是迁移到桌面 Agent 管理应用。

## 推荐组合

两者可以并存，但不建议无目的嵌套：

```text
tmux
├── 通用 SSH 运维
├── 长时间训练、构建和日志
└── 生产环境兜底

Herdr
├── 多 Agent 开发
├── Agent 状态汇总
├── Agent 间编排
└── 开发工作区切换
```

Herdr 运行在 tmux pane 内时，Herdr 只能看到该 pane 的前台 `tmux` 进程，不能穿透内层 tmux 识别其中的 Agent。必须嵌套时，应明确谁负责持久化、谁负责布局，并为两层配置不同 prefix。

## 共同机制边界

二者都通过后台 server 持有伪终端（PTY）和子进程，客户端退出后可以重新连接。因此它们保护的是：

```text
终端客户端断开
    ↓
后台 server 仍存活
    ↓
PTY 和子进程继续运行
```

它们不等于进程检查点：

```text
机器重启 / server 被杀死
    ↓
原进程已经结束
    ↓
不能仅靠恢复布局让进程从原指令位置继续
```

需要跨主机重启、崩溃自动拉起、资源限制和依赖管理时，应使用 systemd、容器编排、Slurm 或专门的任务系统，而不是把终端复用器当作服务管理器。

## 资料维护原则

- 产品能力优先引用官方文档；
- 公开文章和用户反馈只用于记录操作体验和失效线索，不独立证明可靠性；
- 具体接口会随版本变化，涉及 Herdr 时记录核查日期；
- “状态为 done”只表示工具观察到的交互状态，不等价于代码正确、测试通过或任务完成；
- 新经验只有在改变选择、配置、排错或安全边界时才补充，避免堆砌快捷键和零散技巧。
